No permessage-deflate, no router-initiated pings (not needed yet).
- [x] Handshake timeout: `[server] handshake_timeout_ms` (default 10 s, 0 = off) closes connections that do not become an established session in time (covers TLS, RawSocket/WebSocket handshake, HELLO, auth); counted per shard.
- [x] Connection limits: `[server] max_connections` (default "auto" = open-file limit minus 128; the soft limit is raised to the hard limit at startup) and `max_connections_per_ip` (default off), enforced at accept by `ConnectionLimiter`; rejections counted and logged; accept errors (EMFILE) back off instead of spinning. Not done: per-address rate limiting of new connections, per-session message rate limits.
- [ ] JSON (`wamp.2.json`, WebSocket text frames) and MessagePack (`wamp.2.msgpack`) serializers. The CBOR codec is used directly by `wamp_serializer.hpp`, `WampSession` and the handlers (`get_message_type_from_cbor`, `serialize_*`), and `EventTemplate` splices CBOR bytes by layout, so this needs a serializer seam (per-session codec) and a JSON `EventTemplate`; RawSocket would also need to accept serializer 1 (JSON) / 2 (MessagePack) in its handshake.
- [ ] Pattern-based subscriptions/registrations, call cancellation, progressive results.
- [ ] Payload delegation: WAMP Payload Passthru Mode (advanced profile), so the router routes opaque payloads in an application's own protocol (protobuf, gRPC messages, custom envelopes, end-to-end encrypted data) without decoding them. Motivation: feedback that a router which delegates the protocol elsewhere is useful; today `WampList`/`WampDict` hold only string, int64 and bool (no bytes, doubles, null or nesting), so such payloads cannot be carried at all. Steps:
  1. A bytes type in `WampValue` (`wamp_messages.hpp`) and bytes encode/decode in `cbor.hpp` and the `fast::Fields` readers (`wamp_serializer.hpp`); round-trip tests against the nlohmann oracle. Useful on its own.
  2. Parse and validate the `ppt_*` options (`ppt_scheme`, `ppt_serializer`, `ppt_cipher`, `ppt_keyid`) on PUBLISH, CALL, YIELD and ERROR; the payload is a single binary first argument and is never inspected.
  3. Forward the options and the blob unchanged on EVENT, INVOCATION, RESULT and ERROR, including the cross-shard path: `EventTemplate` splices the serialized EVENT, so it must carry the options and the blob (check `frame_for` and `CrossPublish`).
  4. Feature negotiation: announce `payload_transparency` in WELCOME and the roles; remember what each peer announced (per session); answer `wamp.error.feature_not_supported` when a callee or subscriber lacks it; define what a publish with passthru does for subscribers that lack support (skip them, per the spec's wording).
  5. Authorization: optionally let rules match `ppt_scheme` (`authorizer.hpp`, `[[roles.<name>.rules]]`), so a role can be limited to certain payload protocols.
  6. Tests: unit (options, errors, feature gating), end-to-end over RawSocket and WebSocket, cross-shard pub/sub and RPC with a blob, and a size/regression check that normal messages are not slower (`wamp_bench`, `wamp_load`).
  7. Docs: README (what the router does and does not do with passthru payloads), architecture notes, and a client example (Autobahn|Python supports `ppt_*`).
  Out of scope here (a separate task if wanted): a gateway for HTTP/MQTT/gRPC clients, and delegating authentication or authorization to an external service (WAMP's dynamic authenticator/authorizer procedures).
- [ ] Modern C++ clean-up (from a code review; nothing compiled or profiled, so measure before and after where it touches a hot path). In priority order:
  1. Named concepts for the template parameters: promote `is_tls_socket` (`wamp_server.hpp`) to a concept and add a `WampSocket` concept constraining `handle_wamp_session`, `read_some`, `session_reader`, `session_writer`, `handle_socket_read_completion` and `set_socket_options`; `std::invocable<...>` for `Router::post_to_shard<F>`, `Fields::map<Fn>`; a documented `Extractor` concept for `decode<T, Extractor>` (`wamp_serializer.hpp`, "reads the fields in wire order" is only a comment today). Goal: errors that name the failed constraint instead of an instantiation trace. Highest value, lowest risk.
  2. `std::function` -> `std::move_only_function` for `EventCallback`, `InvocationHandler` (`wamp_client.hpp`) and the cross-shard `ShardGroup::Handler`: stored once, called many times, no copy needed. Check libc++ 18 support first (Docker image) and the callers that copy the callbacks.
  3. Audit `noexcept` on move constructors/assignments and small accessors of hot-path types (`EventToSend`, `PendingCall`, `CrossMessage` members, `EventTemplate`, `WriteLock`, `FrameHeaderBytes`): a throwing move makes `std::vector` reallocate by copying. Add `static_assert(std::is_nothrow_move_constructible_v<...>)` for the ones that must be.
  4. `await_reply<Reply, Channel>` (`wamp_client.hpp`) is only used with one channel type: make it a concrete signature.
  5. Decoding throws `MalformedMessage` / `cbor::DecodeError` internally (`Fields`, `decode`, `cbor::Reader`) and converts to `std::expected` at the boundary. Malformed input can be attacker-driven, so exception cost is a DoS lever: measure a flood of malformed messages; if it matters, give `cbor::Reader` an error-returning mode. A trade-off, not a bug.
  6. Optional: `std::byte` / `std::span<const std::byte>` for the RawSocket header and CBOR byte handling, `std::endian`/`std::bit_cast` for the manual shifts, `consteval` for constant tables. Low value unless it catches real bugs.
  Not needed: `std::format` (spdlog `{}` covers it).
